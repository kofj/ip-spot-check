# 审查实践

**最后更新**：2026-10-31

## 多模型评审

### 三角验证

1. **主模型**：主要开发
2. **独立评审模型**：新视角
3. **规则检查**：静态分析

### 验证优先级

发现冲突时依次看：权威来源（文档/规范）→ 代码实际行为 → 第三个模型。

### 假阳性处理

约一半发现是假阳性。每条独立验证，假阳性记入 review log。

## 评审类型

### 设计评审（Gate 2）

- [ ] 目标清晰具体
- [ ] 非目标明确
- [ ] 假设可验证
- [ ] 验收标准可度量
- [ ] 回滚方案已定义

### 代码评审（Gate 4）

- [ ] 代码符合设计
- [ ] 关键路径有测试
- [ ] 无未记录的行为
- [ ] **源降级行为正确**（本项目重点）
- [ ] **措辞未越界**（本项目重点，见工程原则第 5 条）

## 本项目特有检查项

| 检查 | 说明 |
|---|---|
| 是否出现了总分 | 任何形式的合并评分都是违规 |
| 是否有主观定性 | "是攻击者"这类措辞一律打回 |
| 源失败是否静默 | 吞掉错误、显示旧值都算缺陷 |
| 缓存是否有双重计数 | 缓存命中率是额度生命线 |
| 是否有未标注来源的字段 | 每个数据点必须能追溯 |
